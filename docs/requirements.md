# Умный бюджет

Приложение помогает распределять доход, следить за расходами и копить на цели.

## Возможности

- Категории и месячные лимиты в суммах или процентах. Сумма процентов — 100%.
- Импорт за выбранный месяц из локального псевдо-банка: вручную и периодически по планировщику. Повторный импорт не создаёт дубли.
- Классификация по мерчанту, MCC и ключевым словам; ручная смена категории.
- Дашборд «факт / план», топ расходов, предупреждения на 80% и 100% лимита.
- Центр уведомлений и Web Push. Push отправляет отдельный микросервис notifications по событиям Kafka.
- Цели: сумма, дедлайн, накопления и рекомендуемый месячный взнос.
- История изменений категорий и событий.
- Интерфейс в общей стилистике Т-Банка без логотипа.

## Правила проекта

Деньги считаем в копейках, в API передаём строками. Валюта первого этапа — RUB. Бюджет относится к месяцу в часовом поясе пользователя. Для бюджета выбирается один режим: суммы или проценты. Плановый доход задаёт пользователь; импорт его не меняет. Проценты храним целыми сотыми долями процента; остаточные копейки распределяем по наибольшему дробному остатку, при равенстве — по ID категории. Сумма фиксированных лимитов не превышает плановый доход.

Импорт обходит все страницы источника. При сбое сохраняет уже загруженное и позволяет продолжить без дублей. В первом этапе псевдо-банк отдаёт неизменяемые проведённые операции; возвраты и исправления банковских сумм пока вне объёма.

Правила применяются по приоритету, при равенстве — по ID; используется первое совпадение. Условия одного правила соединяются «И»: мерчант без учёта регистра и крайних пробелов, точный MCC, ключевое слово в тексте без учёта регистра. Без совпадения операция остаётся без категории. Новые правила действуют на новые операции; повторное применение к месяцу запускается явно.

Ручной выбор категории сохраняется при повторном импорте и применении правил. Дашборд отражает изменение сразу после сохранения. Неразобранные расходы входят в общий расход; доходы и переводы его не уменьшают.

Каждый порог уведомляет один раз на пользователя, категорию и месяц. При скачке через 80% и 100% создаются оба сообщения. Создание или изменение лимита тоже проверяет текущий расход. Снижение расхода не удаляет уведомление и не разрешает повторную отправку этого порога. Нулевой лимит показывается как незапланированный расход без деления на ноль. История сохраняется при архивировании категории.

Накоплено по цели — сумма записанных взносов; прогресс — накопленное / целевая сумма, максимум 100%. Целевая сумма положительна. Взносы учитывают накопления и не выполняют банковских переводов. Рекомендуемый взнос — остаток, делённый на число календарных месяцев до дедлайна включительно, с округлением вверх до копейки. Текущий месяц учитывается. Например: остаток 9 000 ₽, октябрь–декабрь — 3 000 ₽ в месяц. Достигнутая цель имеет взнос 0; просроченная с остатком — без рекомендации. Повтор записи взноса не увеличивает накопленное.

Пользователь видит только свои данные. Аудит хранит автора, время и старое/новое значение изменения. Отказ в разрешении на push не мешает пользоваться центром уведомлений.

## Вход в MVP

Регистрация и вход — по email и паролю, выход — из текущей сессии устройства. Email без учёта регистра уникален. Пароль содержит минимум 8 символов и максимум 72 байта UTF-8. При регистрации задаётся часовой пояс пользователя (по умолчанию UTC).

Пользователь остаётся авторизован до 30 дней с обновлением короткоживущего JWT. Выход отзывает текущую сессию. Анонимные аккаунты и перенос старых демо-данных не поддерживаются. Подтверждение email и восстановление пароля не входят в текущую реализацию.


## Сессии и push

Закрытие вкладки не прекращает подписку. Push разрешён пока действует привязанная серверная сессия (до 30 дней), даже если короткий access JWT уже истёк. Выход отзывает сессию на сервере и прекращает новые отправки для неё; недоступность проверки авторизации откладывает отправку. Уже принятый провайдером push может прийти позже, поэтому его текст нейтральный, подробности доступны после входа. Другие браузеры имеют собственные сессии и подписки.

Смена аккаунта синхронизируется между вкладками. Запросы со старым отображаемым аккаунтом не должны изменять данные нового аккаунта из общих cookie. Частичное отключение push должно отдельно отражать состояние браузера и сервера и позволять повторить незавершённую очистку.
