# Smart Budget

Go backend и frontend на React + TypeScript. На backend работают регистрация/вход по email и паролю, JWT + refresh-сессии и Web Push: подписка через API, outbox → Kafka → notifications. Frontend — макет бюджета из main, авторизация и push к нему пока не подключены. PostgreSQL — pgx, sqlc и goose. Есть базовые users, auth_sessions, ledger_periods и audit_log; финансовые функции пока в плане.

## Устройство проекта

- Go-модуль — `backend/`; Go-команды выполняются оттуда. Корневой `go.work` подключает модуль для IDE.
- Архитектура: один Go-модуль, отдельные контейнеры API, worker и notifications. Worker публикует outbox в Kafka; notifications потребляет события и отправляет push.
- SQL сервисов — `backend/queries/`; методы генерируются sqlc в `backend/internal/db/`. После изменения SQL или миграций запускай `make generate`; сгенерированные файлы не редактируй вручную. Административный DDL мигратора и проверочные запросы тестов остаются вне sqlc.
- Frontend — `frontend/src/`, обычный CSS и `fetch`. Пакеты, интерфейсы и зависимости добавляй под текущую задачу.
- При переносе файлов учитывай Docker, Makefile, CI и README. Backend доступен через nginx `/api/`, без отдельного порта на хосте.

## Ограничения

- Деньги — целые копейки, в JSON — строки; проверяй переполнение. Месяц и дедлайн — в часовом поясе пользователя, в тестах время задано явно.
- Финансовые изменения месяца сериализуются через `ledger_periods`; данные, аудит и outbox записываются одной транзакцией. Дашборд читает PostgreSQL сразу после сохранения.
- Notifications владеет своей схемой с подписками, inbox и задачами доставки. Inbox и задачи сохраняются до commit offset; внешний push выполняется вне DB-транзакции.
- Проверяй владельца пользовательских данных. Применённые миграции не переписывай.
- Сохраняй чужие изменения. Коммиты, удаление volumes и остановка чужих контейнеров — только по поручению. Секреты не включай в код и логи.

## Завершение задачи

Доводи запрошенное изменение до рабочего результата: исправляй вызванные им сбои и проверяй затронутый сценарий. Для обычных правок и локальных проверок отдельное подтверждение не нужно.

Основные команды выполняй через Makefile из корня; нужен запущенный Docker. Выбирай проверки по изменению:

- `make generate` — генерация sqlc в Docker; `make check-generated` — проверка актуальности, также запускается в CI.
- `make lint` — golangci-lint и frontend lint; `make lint-fix` — автоисправления.
- `make test` — Go-тесты и проверки настоящих Kafka и PostgreSQL.
- `make up` — сборка и запуск API, frontend, worker, notifications, Kafka и PostgreSQL. Приложение — `http://localhost:3000`, health — `/api/health`.
- `make migrate` — применить SQL-миграции; `make migrate-status` — их состояние.
- `make logs` — логи; `make down` — остановка с сохранением данных.
- DB/Kafka: затронутые сценарии транзакций, повторной обработки и восстановления проверяются на настоящих сервисах.
- Только документация: ссылки и `git diff --check`.

Прямые Go/npm-команды используй для точечных проверок, которых нет в Makefile; запускай их из `backend/` или `frontend/` соответственно.

В результате кратко укажи, что изменено, что проверено и что осталось нереализованным или непроверенным.
